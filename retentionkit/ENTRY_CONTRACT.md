# Standard entry integration contract

Correction ticket10 interface checkpoint; the full example/consumer/device correction remains pending. Reuse the existing entry ledger, and select only the envelope that arrived or was restored with the current Activity.

- `OnboardRetentionBridge(splashActivity, hostCanPresent = { true }, entryAdPolicy = RetentionEntryAdPolicy.STANDARD, mainActivity = MainActivity::class.java)`: standard router uses actual `SplashEntry.intent` (`NEW_TASK | CLEAR_TASK`). Default entry interstitial policy stays in OnboardKit. `WITHOUT_SPLASH_ADS` is explicit opt-in. Original one-argument and trailing-lambda constructors remain source compatible.
- Notification sources map to NOTIFICATION; WIDGET/SHORTCUT to WIDGET; feedback destination or FEEDBACK source to UNINSTALL. All rescue taps reopen Splash and preserve the FEEDBACK source.
- `bridge.mainIntent(context, mainActivity, outcome): Intent?` signals the existing terminal state and copies only the outcome passthrough. Completed/legitimate Skipped route Main; Aborted returns null. The existing listener retains its other responsibilities.
- `kit.mainHandoff(activity, savedInstanceState, featureRouter: RetentionRouter): RetentionMainHandoff`: bind during Main.onCreate, before onStart. The helper observes resumed/pause/destroy, retries readiness at most 10 seconds per resume and owns bounded resume-suppression handles. Forward `onNewIntent(intent)` and `onSaveInstanceState(out)`. `close()` is idempotent and automatic on destruction; `hasPendingEntry` reads only the selected pending token.
- Main forwarding retains the exact materialized envelope and **does not consume** feature entries. The final router must return an explicit in-package feature Activity, or null to leave it pending. It may validate known retired aliases without rewriting the token/destination. Final feature capture/dispatch owns consume. Failed routers remain retryable; an already-forwarded selection survives recreation. No arbitrary old backlog entry is selected.
- Configure `mainActivity` on the bridge. Main never passes automatic PROMPT eligibility. Explicit ENTRY requires the host predicate, actual resumed/foreground Activity and all shared onboarding/ad/external-transition gates. Main continuation validates its exact selected pending ONCE envelope in the helper; an explicit menu start via `feedback.openViaEntry()` needs no pre-existing token. The host predicate expresses dialog/focus readiness and should not duplicate the helper’s pending-token check, which would block such menu starts. The helper reserves resume suppression before Main.onStart. It does not create another interstitial.
- A non-Onboard host can use vendor-free `RetentionSplashRouter(splashActivity: Class<out Activity>)` from core, then forward the rewritten envelope through its own Splash/setup and Main. The low-level `RetentionRouter` remains available for deliberately custom integrations.

## Feedback

`feedback.openViaEntry(): FeedbackShowResult` is the standard menu/button entry. It routes through configured Splash; only Main-ready `handleEntry(materializedEntry)` launches the SDK session Activity. `show()` remains an advanced direct PROMPT API. A blocked explicit entry stays pending; consumption occurs only immediately before the final survey launch. Accepted platform start followed by failure/process death remains at-most-once, not guaranteed exactly-once navigation.

`FeedbackOptions` appends `systemAction = UNINSTALL_CONFIRMATION`, `appManagementFallback = true`, and `nativeContent: FeedbackNativeContent? = null`. Default Continue uses Android `ACTION_UNINSTALL_PACKAGE` and the merged `REQUEST_DELETE_PACKAGES` permission. Android/user owns confirmation. Failed launch can fall back to App Info after rechecking the same scope/config/session. `APP_MANAGEMENT` selects App Info explicitly; existing `controller.continueToAppManagement()` remains. No action/event claims successful uninstall.

The existing `FeedbackUiFactory.create(activity, controller, content): View` stays source compatible. `RetentionFeedbackActivity` is a `LifecycleOwner`. `FeedbackNativeContent.bind(activity, lifecycleOwner, container: ViewGroup): AutoCloseable` is vendor-free. Default UI creates a slot; a custom factory calls `controller.bindNative(itsContainer)` once per slot. Controller owns native bindings until destroy, including recreation; `controller.lifecycleOwner` exposes lifecycle for other custom content. Use controller actions `selectReason`, `keep`, `tryFeature`, `continueToSystem`, and optional explicit `continueToAppManagement`; never replace the state machine. Reasons remain optional. The custom Activity retains system/IME insets and durable session restoration.

Construct a **new bridge per new runtime install** (including tests calling uninstallForTests); shutdown cancels its subscriptions. Do not reuse a detached singleton adapter. Repeated install without teardown still returns the original facade.
